Gloamwake — Deployment Plan

Cloudflare vs DigitalOcean · Convex self-hosted backend + Vite SPA · Prices checked Oct 2026

Key insight: Cloudflare alone cannot host this app. Pages / Workers / R2 handle the static frontend, DNS, CDN and WAF — but the convex-backend Docker image (ports 3210 API+WebSocket, 3211 site/Auth) needs a VM. Realistic options are Convex Cloud (managed) or DigitalOcean (self-hosted), ideally with Cloudflare in front of DO.

3. Database: managed service vs self-managed

Managed Postgres recommended when growing

  • Automatic daily backups + 7-day point-in-time recovery, failover standby, patching, metrics.
  • No 3am disk-full / corrupt-SQLite pages. Scales past ~10s GB and concurrent writes.
  • DO Managed PG 1 GB / 1 vCPU / 10 GB: $15.15/mo single node. Set POSTGRES_URL in compose override + S3 storage.
  • Downside: cost floor; still need logical convex export for portable backups.

Self-managed (SQLite volume today)

  • Fine for prototype: one file in convex-data, zero extra cost.
  • You own: snapshots, offsite copy, WAL/replica (if Postgres), restore drills.
  • Risk: single-disk failure = data loss without tested offsite copy.

Backup recipes

# SQLite volume — nightly cron on the host, plus DO volume snapshots
docker run --rm -v click-hunter_convex-data:/data \
  -v "$PWD/backups:/backup" alpine \
  tar czf /backup/convex-data-$(date +%F).tgz /data
rclone copy ./backups/ r2:click-hunter-backups/   # offsite, encrypted

# Logical backup — weekly (portable across SQLite ↔ Postgres ↔ Cloud)
npx convex export --path ./backups/convex-$(date +%F).zip

# If on Postgres: nightly pg_dump + WAL archiving (wal-g → Spaces/R2),
# one async replica in another region, documented promote steps.

Retention: 7 daily + 4 weekly. Restore-drill quarterly on a staging droplet (down -v + import). Pin CONVEX_BACKEND_VERSION to your convex npm version on every upgrade.

4. Security & safety checklist

Network & host

  • DO Cloud Firewall: allow 80/443 (and 22 from your IP only). Everything else denied.
  • Dashboard :6791 on 127.0.0.1 or Tailscale only — never public.
  • Reverse proxy (Caddy/nginx) terminates TLS, forwards Upgrade headers to :3210.
  • Cloudflare proxy ON (Full Strict), HSTS, WAF rules for auth/arena/bazaar abuse paths.
  • SSH keys only, non-root deploy user, unattended upgrades, fail2ban.

Secrets & app

  • CONVEX_SELF_HOSTED_ADMIN_KEY, JWT_PRIVATE_KEY/JWKS in host env / password manager — never git (docker/.env.selfhosted is gitignored).
  • Rotate admin key via generate_admin_key.sh; rotate JWT with dual-JWKS overlap.
  • Keep server-side settlement (boss/arena) authoritative; rely on existing rate-limiter for chat/market.
  • Uptime check on /version, log shipping, backup-encryption + offsite versioning.
  • CI: pin images, Dependabot, backend:push + smoke test before promoting.

6. Deployment sequence

  1. Provision: VPC + Droplet (Ubuntu LTS) + Firewall + reserved IP + Spaces bucket + optional Managed PG.
  2. DNS/TLS: Cloudflare records — app → droplet, convex → :3210, convex-site → :3211. Full Strict, proxied.
  3. Harden + install: SSH keys, updates, Docker, clone repo, cp docker/.env.selfhosted.example docker/.env.selfhosted.
  4. Secrets: compose up -d backend → generate_admin_key.sh → generate-auth-keys.mjs → convex env set JWT_PRIVATE_KEY / JWKS.
  5. Push backend: pnpm backend:push with public CONVEX_SITE_URL. Verify crons (arena expiry hourly, ranked Monday).
  6. Ship frontend: compose web rebuild with public build args, or Pages deploy of dist/.
  7. Data: Admin reseed for fresh, or convex export (cloud) → convex import (self-hosted).
  8. Operate: snapshot + backup crons, /version uptime, log retention, CI deploy hook, quarterly restore drill.
